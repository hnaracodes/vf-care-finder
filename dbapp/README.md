## Deploy: pipeline on Databricks (the brief's "run on Databricks")

1. Upload the repo to your workspace. `databricks sync` skips what `.gitignore` lists (the deploy docs give `.gitignore` as the way to exclude files), so `data/`, `.venv/` and `node_modules/` stay local. Look at the dry run first:

   ```bash
   databricks sync --dry-run --full . "/Workspace/Users/$ME/cmu-datathon"
   databricks sync --full . "/Workspace/Users/$ME/cmu-datathon"
   ```

2. In the workspace, open `cmu-datathon/notebooks/01_pipeline`, attach serverless compute, check the widgets (catalog and schema names), and choose Run all. The notebook:
   - compares the Marketplace tables with the local export (row counts, columns, `null` cells, rows with NUL bytes), side by side;
   - runs WP1, WP2 Part A and B, WP3 and WP11 through `vf.io`'s Databricks source;
   - writes `dbapp/bundle/` and `dbapp/vf/` into the uploaded repo folder, and prints every bundle and pipeline count next to the local run's `manifest.json`. Any difference is a bug to explain;
   - saves Delta tables `facilities_silver`, `facts_silver`, `capability_grades`, `facility_flags`, `places` in `workspace.vf_datathon` (widgets 3 and 4).

3. Create the app (first time only). Creating it also starts its compute:

   ```bash
   databricks apps create "$APP" --description "Find the right care: cited facility answers with stated uncertainty"
   ```

4. Deploy from the uploaded folder:

   ```bash
   databricks apps deploy "$APP" --source-code-path "/Workspace/Users/$ME/cmu-datathon/dbapp"
   ```

5. Wait for the deploy to succeed, then read the URL:

   ```bash
   databricks apps get "$APP" -o json | jq '{url, app_status, compute_status}'
   ```

6. Open the URL, run the brief's five scenarios, and write the URL at the top of this file.

## Deploy: bundle built locally (faster, for a quick redeploy)

Use this when the local pipeline outputs are current and you only want the app updated.

```bash
.venv/bin/python scripts/wp12_bundle.py        # writes dbapp/bundle and dbapp/vf; exits 1 if a file is over 10 MB
databricks workspace import-dir dbapp "/Workspace/Users/$ME/vf-care-finder" --overwrite
databricks apps deploy "$APP" --source-code-path "/Workspace/Users/$ME/vf-care-finder"
```

`import-dir` is used here, not `sync`, because `bundle/` is git-ignored and `import-dir` skips only `.git`, `.databricks` and `node_modules` (`databricks workspace import-dir --help`). `--overwrite` replaces files but does not delete old ones; if a file was removed from the bundle, delete the workspace folder first with `databricks workspace delete --recursive "/Workspace/Users/$ME/vf-care-finder"`.

## Restart before judging (D034)

On Free Edition an app runs for up to 24 hours after it was started, updated or redeployed, then stops on its own. Restart it shortly before anyone judges it:

```bash
databricks apps get "$APP" -o json | jq '{app_status, compute_status, url}'   # is it running?
databricks apps stop "$APP"                                                    # then start again,
databricks apps start "$APP"                                                   # which restarts the 24-hour clock
```

If it is already stopped, `databricks apps start "$APP"` is enough. Redeploying (step 4) also restarts the clock. Then open the URL once and run "dialysis near Jaipur" to confirm it answers.

If it does not come up:

```bash
databricks apps logs "$APP" --tail-lines 300            # app and system logs
databricks apps list-deployments "$APP"                  # did the last deploy succeed?
```

## Limits that bite

- **10 MB per file.** "App files can't exceed 10 MB. If any file in the app directory exceeds this limit, deployment fails with an error." Since D043 the keyword matrix is saved in parts (`matrix.part-NNN.npz`). Build of Nov 21 late evening: 45.8 MB in all, 42 files in `dbapp/`, largest `bundle/places.parquet` at 6.8 MB, nothing over the limit. The bundle script reports any file over the limit and exits 1.
- **`bundle/.gitignore` says `*`.** It keeps the bundle out of git. `databricks sync` honours it (so the pipeline route rebuilds the bundle in the workspace), and `import-dir` does not. The deploy docs do not say whether `apps deploy` reads `.gitignore` files. After every deploy, check that `/api/health` shows `mode: bundle`. If it shows `local` or an error, the bundle did not make it into the app.
- **Pickled vectorizer.** `bundle/keyword_index/vectorizer.pkl` was written with scikit-learn 1.9.1 and numpy 2.5.5 (local), and it loads under the pinned 1.9.1 and 2.4.6 on Python 3.11 (checked). Keep `scikit-learn` pinned to the version that built the bundle.
- **Up to 3 apps per account**, serverless compute only, and outbound internet from serverless is limited to trusted domains. The notebook installs one package with `%pip` (`rapidfuzz`) and calls no external API.
- **Do not share the app outside the workspace.** The facilities table's reuse terms are unchecked. Changing app permissions beyond your workspace is a public step: prepare it and ask Hruday.
